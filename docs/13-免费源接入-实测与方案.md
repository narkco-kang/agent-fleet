# 13 · 免费源接入：dsh-our-free-model 研究与 AgentMesh 落地

> 参考项目：<https://github.com/Ebony-Vinyl/dsh-our-free-model>（第三方 DSH 插件，MIT）
> 目标：不照搬插件，只吸收「公开免密上游 + 免费模型池 + 本地转发」的可复用部分，接入 AgentMesh 的智能路由网关。

## 1. 参考项目关键事实

| 项 | 内容 |
|---|---|
| 形态 | DSH 插件（纯插件挂载、零依赖、无构建步骤） |
| 免费车道 1 | OpenCode：`https://opencode.ai/inference/v1/*`，`Authorization: Bearer public` |
| 免费车道 2 | Kilo：`https://api.kilo.ai/api/gateway`，无需 Authorization，模型池含 `kilo-auto/free` |
| EAC 车道 | 自建网关，HMAC + GitHub 授权令牌（需登录 GitHub 并 star），桌面端专属 |
| 聚合车道 | 76 家 provider，需要用户自带 Key（`registry.json`） |
| 本地转发 | `GET /v1/models`、`POST /v1/chat/completions`、`/v1/responses`、`/v1/messages`、`/health`，默认 `127.0.0.1:18899` |
| 签到 | **没有公开签到 HTTP 端点**；只有「一键领取积分」UI（LobsterAI/Qoder/TRAE/Cline 等），具体 URL 未披露 |
| 额度模型 | 无套餐额度，但上游按 session 限速；打满返回 429 |
| 安全提醒 | npm 裸名 `dsh-our-free-model` 是第三方篡改版，官方是 `@ebony-vinyl/dsh-our-free-model` |

## 2. 本机实测（2026-11-01）

| 源 | 端点 | 结果 |
|---|---|---|
| 本地 modelgateway | `POST 127.0.0.1:18765/v1/chat/completions`，`free-models/kilo-auto/free` | **502** `{"error":"全部线路失败","code":"ALL_FAILED","tried":[]}` |
| 本地 modelgateway | `GET 127.0.0.1:18765/health` | 404（进程可达，已兼容为可用） |
| Kilo 直连 | `POST https://api.kilo.ai/api/gateway/v1/chat/completions`，`kilo-auto/free` | **200 OK**，`cost=0`，返回 `pong` |
| OpenCode 直连 | `POST https://opencode.ai/inference/openai/v1/chat/completions`，`big-pickle` | **429** `FreeUsageLimitError`（免费额度需在 OpenCode 客户端/订阅内使用） |

结论：**免费源本身可用（Kilo），但本地 modelgateway 的免费线路是空的（tried=[]）**。AgentMesh 不应把「网关 ALL_FAILED」当成「免费源不可用」。

## 3. AgentMesh 落地

### 3.1 直连免费源目录

`backend/src/services/routing/freeSourceCatalog.ts`

- 内置 `kilo-free`（无需 Key）与 `opencode-free`（Bearer public，额度受限）。
- `resolveBaseUrl` 支持 `FREE_KILO_BASE_URL` / `FREE_OPENCODE_BASE_URL` 覆盖（自建镜像/测试）。
- 探测用最小 chat 请求（`max_tokens=64`），**content / reasoning / finish_reason 任一存在即视为活响应**，避免思考型模型被误判为空。
- 429 → `quotaLimited`；401/403 → `authRequired`；其余错误保留原文。

### 3.2 免费源探测接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/routing/free-sources` | 角色路由里的免费 ref |
| POST | `/api/routing/free-sources/probe` | 经 modelgateway 探测（含自动签到重试） |
| GET | `/api/routing/free-sources/catalog` | 直连免费源目录 |
| GET | `/api/routing/free-sources/catalog/:id/models` | 拉取模型池并筛免费模型 |
| POST | `/api/routing/free-sources/probe-direct` | 单源真实探测 |
| POST | `/api/routing/free-sources/probe-all` | 网关 + 直连综合探测，返回 `usable` |

CLI：`npm run probe:free --workspace backend`

### 3.3 自动打卡

- modelgateway 返回 401/403/429，或错误文本包含 `checkin / 签到 / 打卡 / quota / free tier` → 自动 `POST /v1/free/checkin`，404 时回退 `POST /v1/checkin`，成功后重试一次。
- **注意**：参考项目没有公开签到端点，因此「自动打卡」只对支持该约定的网关有效；直连 Kilo 无需打卡，OpenCode 的 429 属于额度限制，打卡无法解决。

### 3.4 免费线路兜底执行

`scheduler.executeGatewayTask`：

1. 正常走 modelgateway；
2. 若失败且 `modelRef` 是免费 ref（含 `free` / `kilo-auto/free`），直连 Kilo 重试；
3. 成功则写 `usage_records`（provider = `kilo-free:kilo-auto/free`），任务标记完成。

集成测试：`backend/tests/freeFallback.integration.test.ts`（网关 502 → 直连 200 → 任务完成 + 台账）。

## 4. 免费源评级（优 > 中，只保留优与中）

`backend/src/services/routing/freeSourceRating.ts`：

| 评级 | 中文 | 判定 |
|---|---|---|
| excellent | 优 | 请求成功且延迟 < 1500ms |
| medium | 中 | 请求成功但延迟 >= 1500ms |
| poor | 差 | 请求失败，或 429 额度受限（当前不可用） |

`POST /api/routing/free-sources/probe-all` 返回 `ranked`（仅优/中，优在前）。实测结果：

```
[优] kilo-free:kilo-auto/free (858ms)
```

## 5. 自动签到（对有签到领取积分需求的免费源）

`backend/src/services/routing/checkinService.ts` + `free_checkins` 审计表。

- 签到源注册表：
  - `gateway-free`：经 modelgateway `/v1/free/checkin`（网关配置了免费线路时启用）
  - `opencode-quota`：OpenCode 额度刷新（端点未公开，配置 `FREE_OPENCODE_CHECKIN_URL` 后启用）
- 定时自动签到：`startCheckinLoop()`，间隔 `FREE_CHECKIN_INTERVAL_MS`（默认 6h）
- 接口：`POST /api/routing/free-sources/checkin`（手动）、`GET /api/routing/free-sources/checkin/status`
- 每次签到（成功/失败）都写 `free_checkins` 审计记录

注意：参考项目没有公开签到端点，因此 HTTP 签到端点一律可配置；未配置则跳过并记录 `disabled`。
