# AgentFleet 适配器开发指南（30 分钟上手）

> 本文教你如何把一个平台从「探测骨架」升级为「可真实直连执行」的 Adapter。
> 参考实现：`device-agent/src/adapters/grokAdapter.ts`（当前唯一稳定真接的模板）。

---

## 一、先理解现状：三种 Adapter

AgentFleet 把「每台设备上已安装的 agent 平台」抽象成统一接口 `Adapter`（`device-agent/src/adapters/adapter.ts`）：

```ts
export interface Adapter {
  readonly agentType: AgentType;
  readonly displayName: string;
  detect(): Promise<AdapterDetection>;            // 探测本机是否安装 + 版本 + 可执行路径
  run(task: TaskSubmit, sink: AdapterEventSink): Promise<AdapterRunHandle>; // 真接执行任务，流式回传
  cancel(taskId: string): void;                    // 取消任务
}
```

当前 13 个平台的实现分两类：

| 类型 | 文件 | 说明 |
|------|------|------|
| **真接 Adapter** | `grokAdapter.ts` | `detect` + `run` 都已实现，能真实跑任务。**唯一稳定** |
| **骨架 Adapter** | `catalogAdapter.ts` | `detect` 已实现（从 `platformCatalog.ts` 目录表读取），但 `run` 是占位（直接回传 `failed`） |

**你要做的事**：把某个平台的「骨架」升级为「真接」——即新写一个 `<platform>Adapter.ts`，实现 `run()`，照抄 `grokAdapter.ts` 的骨架。

---

## 二、五步上手（照抄 grok 模板）

### 第 1 步：新建适配器文件

在 `device-agent/src/adapters/` 下新建 `<platform>Adapter.ts`，复制 `grokAdapter.ts` 全文，把类名、`agentType`、`displayName`、探测路径、命令参数改掉。

```ts
// device-agent/src/adapters/claudeAdapter.ts（示例）
export class ClaudeAdapter implements Adapter {
  readonly agentType = 'claude' as const;
  readonly displayName = 'Claude Code';
  // ... 其余照抄 grokAdapter.ts
}
```

### 第 2 步：确认探测逻辑

`detect()` 要能找到本机已装的可执行文件。两个来源：

1. 固定候选路径（`os.homedir()` 下）——参考 `grokAdapter.ts` 的 `findGrok()`；
2. `platformCatalog.ts` 里已配好的 `commands` / `defaultDirs` / `npmPackages`。

> 若平台已在 `platformCatalog.ts` 里，`detectPlatform()`（`detector.ts`）已经能探测；你只需在 `detect()` 里调用它，或沿用 `CatalogAdapter` 的探测逻辑。

### 第 3 步：实现 `run()`（核心）

`run()` 的职责：把 `task.prompt` 交给平台 CLI 的 **headless 模式**，spawn 子进程，把输出规范成 `TaskEvent` 流回传。核心依赖 `runProcess`（`device-agent/src/runner/processRunner.ts`）。

参考 `grokAdapter.ts` 的写法：

```ts
const handle = runProcess(
  task.taskId,
  {
    cmd: detection.executable,
    args: ['--single', task.prompt, '--output-format', 'streaming-messages-json', '--always-approve'],
    stdin: undefined,
    env: {},
    onLine: (_line) => {},
  },
  sink,
  makeSeq,
);
handle.done.then(({ code }) => {
  sink({ taskId: task.taskId, seq: makeSeq(), eventType: 'status',
         status: code === 0 ? 'completed' : 'failed',
         data: { message: code === 0 ? '执行完成' : `退出码 ${code}` }, ts: Date.now() });
});
```

**关键点**：每个平台的 headless 参数都不同，这是本任务唯一需要你实测的部分。已知 grok 用：

```
grok --single "<prompt>" --output-format streaming-messages-json --always-approve
```

其他平台的 headless 入口（**以下仅为常见线索，务必以各平台官方文档为准实测**）：

| 平台 | headless 线索（需实测确认） |
|------|---------------------------|
| Claude Code | `claude -p "<prompt>"`（print / non-interactive） |
| Codex | `codex exec "<prompt>"` |
| Aider | `aider --message "<prompt>"`（或 `--yes`） |
| Gemini CLI | `gemini -p "<prompt>"` |
| Qwen Code | `qwen chat "<prompt>"`（headless 模式） |
| Kimi CLI | `kimi chat "<prompt>"` |
| Cody | `cody chat -m "<prompt>"` |
| OpenCode | `opencode run "<prompt>"` |
| Windsurf / Cursor / DSH / MarsCode | 多为 GUI/登录态，headless 能力需先确认 |

> **原则**：宁可不写，不要瞎写。headless 参数查官方 `--help` 或文档确认后再落代码，并在 PR 里附上你实测的平台版本号。

### 第 4 步：注册到 `index.ts`

打开 `device-agent/src/adapters/index.ts`，把该平台的 `CatalogAdapter` 替换成你的新类：

```ts
export const adapters: Adapter[] = [
  new GrokAdapter(),
  new ClaudeAdapter(),               // ← 新增
  ...PLATFORM_CATALOG.filter((d) => d.agentType !== 'claude')  // 去掉 claude，避免重复
                       .map((def) => new CatalogAdapter(def)),
];
```

### 第 5 步：测试 + 提交

```bash
npm run build
npm run test --workspace device-agent   # 或参照现有 adapter 测试补一例
```

在 PR 里写明：你本机的平台版本、`detect` 结果、`run` 的一次真实输出。

---

## 三、验收标准（reviewer 会看）

- [ ] `detect()` 能在真实机器上找到该平台（`found: true` + 正确版本号）
- [ ] `run()` 能 spawn headless 命令并流式回传 `TaskEvent`（不是占位 `failed`）
- [ ] `cancel()` 能真正终止子进程
- [ ] 在 `index.ts` 注册，且 `npm run build` + 测试通过
- [ ] PR 描述附平台版本号 + 实测命令

---

## 四、常见坑

1. **headless 参数编造**：最容易被 reviewer 打回的点。每个 flag 都实跑验证。
2. **登录态**：很多平台首次运行要登录（如 grok 需 `grok login` 或 `XAI_API_KEY`）。PR 里说明登录前置条件。
3. **流式输出解析**：不同平台输出格式差异大（纯文本 / JSON 流 / ANSI 颜色码）。`runProcess` 统一解析，但若格式特殊，需在 `onLine` 或 `runProcess` 里补解析。
4. **进程退出码**：部分平台 headless 成功也返回非 0，需据实际情况修正 `completed/failed` 判定。
