# 14 · 平台模型绑定：部署即用 + 故障自动/手动切换

> 目标：一键部署 agent 平台后，直接把「设备 + agent 平台」对接智能路由网关（modelgateway），
> 为不同平台配置模型；模型出问题自动切换兜底，支持手动切换。

## 1. 概念

- **平台模型绑定**：`(deviceId, agentType) → 主模型 + 兜底模型`。
- 部署成功、或手动 API 配置后，该设备的该 agent 平台经 modelgateway 用模型执行任务（而非本地 CLI）。
- 主模型故障 → 自动切兜底；全部失败 → 降级本地 agent；可手动切换/恢复。

## 2. 数据模型

`platform_models` 表（PK = device_id + agent_type）：

| 字段 | 说明 |
|---|---|
| model | 主模型 ref（如 `kimi/k3`） |
| fallbacks | 兜底模型 ref 数组 |
| active_model | 当前生效模型 |
| excluded | 已失败待排除的模型（成功/手动切换后清空） |
| state | `ok` / `degraded` |

## 3. 部署即用

- Excel / JSON 部署目标新增可选列：`deviceId`、`models`（`agentType=model,fb1,fb2` 或 JSON）。
- 部署校验通过后：`bindPlatformModels(deviceId, modelConfigs)` 自动绑定。
- 绑定后，调度器对该设备该平台的任务改走网关模型执行。

## 4. 故障切换

`scheduler.dispatch`：

1. `pickTarget` 选中设备+agent；
2. 若存在健康绑定（`resolve` 返回 state=ok）且网关可用 → 走网关执行；
3. 执行顺序 = `[activeModel, ...fallbacks, model]`，逐个尝试；
4. 失败 → `markModelFailed`（加入 excluded，切到下一个未排除模型）；
5. 全部失败 → `degraded`，任务回到 `queued`，下一轮降级本地 agent 执行。

## 5. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/routing/platform-models` | 列表 |
| POST | `/api/routing/platform-models` | 绑定 `{deviceId, agentType, model, fallbacks}` |
| DELETE | `/api/routing/platform-models/:deviceId/:agentType` | 解绑 |
| POST | `/api/routing/platform-models/:deviceId/:agentType/switch` | 手动切换模型 |
| POST | `/api/routing/platform-models/:deviceId/:agentType/reset` | 手动恢复健康 |
