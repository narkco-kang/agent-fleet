## 0. 一句话定位

AgentFleet = **多设备智能体舰队**：每台设备是一支本地蜂群（设备上已装的 codex/claude/grok/cursor 等真实 CLI agent 平台是工蜂），backend 统一跨设备调度。原名 AgentMesh。

- 目录 `agent-mesh/`（npm workspaces，scope `@agentfleet/*`）
- GitHub https://github.com/narkco-kang/agent-fleet（public / MIT / main）

## 3. 全局「已实现 / 缺失」速查（AI agent 最常问的）

### 3.1 我们有、且是护城河（对外主张的立足点）

1. **跨设备账本一致性**：哈希链 + Merkle + Ed25519 + 补同步 + 篡改拒收（`memory/src/`，114/114 测试）
2. **设备级容错**：秒级断连 + running→queued 自动迁移 + 心跳连续 miss 容忍 + 断点续跑（lost=0）
3. **真实 CLI 平台实机验证**：10 平台（grok 走 ACP / dsh headless / workbuddy HTTP / 其余 cliRunner），三台真实云服务器端到端验证
4. **可依赖编排**：DAG 依赖调度 + 决策门 HITL + 熔断器 + turn 队列幂等（对标 Orca 补齐）
5. **可语义检索**：向量 embedding + 五类语义分层 + Dreaming 自演化 + RRF 混合重排
6. **可沙箱隔离 + 可权限目录**：三态 sandbox + allow/ask/deny 权限目录

### 3.2 我们缺、且是 P0 真空白（融合 openJiuwen 要补的）

**已全部补齐（2026-11-04）**：沙箱隔离、上下文交接摘要、向量检索、五类语义分层、Dreaming 自演化 —— 上述 P0 真空白均已落地（见 2.1/2.2/2.8/2.9）。

### 3.3 我们缺、但属 P1/P2（不致命）

- 陈旧工作区防护（stale-base drift 检查）
- 图遍历检索（实体匹配→图遍历，docs/25 规划未落地）
- 遗忘衰减（Dreaming 已做，衰减未做）
- 共享工作空间（运行时协作）
- 群组感知
- 个人微信（占位）
- 暗色主题（CSS 变量 + MUI darkTheme 已定义，未接线）

## 5. 已知事实校正（凭记忆容易写错，务必核对）

1. **WorkBuddy 执行路径 = HTTP 动态端口网关 + session reply 轮询**（非 ACP `--serve --acp`，代码注释与实现不符）
2. **NeuralGraph 布局 = CSS Grid 两栏**（设备内嵌 agent 可折叠 | 任务可折叠），依赖有 d3-force 但源码零 import
3. **记忆检索 = BM25 + 语义向量（Xenova）+ Jaccard 三路 RRF**（`hybridSearchAsync`）；五类语义分层 + Dreaming 已实现，只写语义索引不写账本
4. **个人微信 = 纯占位**；成本核算 = 有（pricing.ts + usage_records.cost）
5. **RRF 重排已实现**——本项目唯一曾被我误判为"缺失"的能力，现已修正
6. **Orca 不是"工作台"，是完整 coordinator 编排系统**（114,746★，有 DAG/决策门/熔断/联邦跨主机/turn 队列）。之前对比报告"Orca 无自动路由/断线检测/跨设备调度"的判断**已证伪**，详见 `deliverables/Orca调度流程深度调研与对标.md`
