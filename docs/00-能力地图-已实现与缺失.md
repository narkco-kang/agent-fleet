## 0. 一句话定位

AgentFleet = **多设备智能体舰队**：每台设备是一支本地蜂群（设备上已装的 codex/claude/grok/cursor 等真实 CLI agent 平台是工蜂），backend 统一跨设备调度。原名 AgentMesh。

- 目录 `agent-mesh/`（npm workspaces，scope `@agentfleet/*`）
- GitHub https://github.com/narkco-kang/agent-fleet（public / MIT / main）

## 3. 全局「已实现 / 缺失」速查（AI agent 最常问的）

### 3.1 我们有、且是护城河（对外主张的立足点）

1. **跨设备账本一致性**：哈希链 + Merkle + Ed25519 + 补同步 + 篡改拒收（`memory/src/`，112/112 测试）
2. **设备级容错**：秒级断连 + running→queued 自动迁移（lost=0）
3. **真实 CLI 平台实机验证**：10 平台（grok 走 ACP / dsh headless / workbuddy HTTP / 其余 cliRunner），三台真实云服务器端到端验证

### 3.2 我们缺、且是 P0 真空白（融合 openJiuwen 要补的）

1. **沙箱隔离**（grep sandbox=0）
2. **上下文压缩 / 交接摘要**（grep=0，sessions 表无上下文累积）
3. **向量检索 embedding**（当前 Jaccard 降级替代）
4. **五类语义记忆分层**（有图模型，无语义分类）
5. **自演化 / Dreaming / 遗忘衰减**（grep=0）

### 3.3 我们缺、但属 P1/P2（不致命）

- 任务级 checkpoint / 断点续跑
- 多 Session 并行（loop 串行）
- 图遍历检索（docs/25 规划未落地）
- 专属团队代理 Leader 实体
- 成本核算（无价格字段）
- MCP client
- 个人微信（占位）
- 权限目录（tiered_policy）
- 共享工作空间（运行时协作）
- 群组感知
- **调度确定性（对标 Orca 缺口）**：任务依赖 DAG / 决策门 HITL / 熔断器 / turn 队列投递 / 陈旧工作区防护 / 心跳连续 miss 容忍

## 5. 已知事实校正（凭记忆容易写错，务必核对）

1. **WorkBuddy 执行路径 = HTTP 动态端口网关 + session reply 轮询**（非 ACP `--serve --acp`，代码注释与实现不符）
2. **NeuralGraph 布局 = CSS Grid 三栏**（设备|Agent|任务），依赖有 d3-force 但源码零 import
3. **记忆检索 = BM25 + Jaccard + RRF 重排**（无向量 embedding）；fork/selectFork/gossip/catchUp 仅库层有、生产未调用（死代码约 38%）
4. **个人微信 = 纯占位**；cost/成本表 = 无
5. **RRF 重排已实现**（`memory-index.ts hybridSearch`）——这是本项目唯一曾被我误判为"缺失"的能力，现已修正
6. **Orca 不是"工作台"，是完整 coordinator 编排系统**（114,746★，有 DAG/决策门/熔断/联邦跨主机/turn 队列）。之前对比报告"Orca 无自动路由/断线检测/跨设备调度"的判断**已证伪**，详见 `deliverables/Orca调度流程深度调研与对标.md`
