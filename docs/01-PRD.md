# 01 · PRD — AgentMesh 跨设备超级智能体协同系统

> 版本 v0.1 · 产品经理：许清楚 · 状态：待架构评审

---

## 1. 项目信息

| 项 | 值 |
|---|---|
| 项目名 | `agent_mesh` |
| 语言 | 中文 |
| 技术栈（默认） | Vite + React + MUI + Tailwind CSS |
| 产品形态 | Web 看板（桌面优先）+ 设备端守护进程 + 微信入口（个人微信 / 企业微信） |
| 原始需求复述 | 把每台设备上**已安装**的各类 AI agent 平台（Codex CLI、Claude Code、DSH Desktop、Grok 等）统一调度，组成跨设备「超级智能体团队」，支持从 Web / 微信下发任务、实时监控、回收结果 |

**三大既定决策（不改动）**
1. 通信架构：混合——局域网优先（mDNS/Bonjour 发现 + 设备直连）+ 云端 WebSocket 中继兜底（穿透 NAT/防火墙）
2. 设备智能体：不新写 agent 内核，通过统一 Adapter 调度已装平台，运行时自动探测
3. 微信助理：个人微信 + 企业微信都要，作为任务下发入口

---

## 2. 产品定位与目标

**定位**：面向个人开发者 / 技术型小团队的「跨设备、跨异构 AI agent 统一调度层」。不造 agent，只做「发现 + 适配 + 调度 + 可视化」四件事。

**产品目标（3 个，正交）**

| # | 目标 | 衡量标准 |
|---|---|---|
| G1 | 统一异构调度：一套协议适配 Codex/Claude Code/DSH/Grok，用户无感平台差异 | 支持 ≥4 种 agent 平台；新增平台只需加 1 个 Adapter，不改调度核心 |
| G2 | 跨设备无缝协同：设备自动发现、任务智能路由、断线可降级 | 局域网内设备上线 ≤5s 可发现；任务路由成功率 ≥95%（设备在线前提下） |
| G3 | 多入口触达：Web 看板 + 微信双入口，全生命周期可监控 | 微信下发→结果回传 ≤1 轮消息交互；看板状态刷新延迟 ≤2s |

## 3. 目标用户

| 用户 | 画像 | 核心诉求 |
|---|---|---|
| 康（主要） | 个人开发者，中文用户，多台设备（Mac / PC / 手机），每台装了不同 agent | 一台设备用不了的能力，自动用另一台的；人不在电脑前也能远程指挥 |
| 技术型小团队（扩展） | 2–10 人工作室，共享算力与 agent 能力 | 多人共用一个设备池，任务排队、认领、权限隔离 |

## 4. 用户故事

> 覆盖 8 类核心场景，前 6 条对应任务要求的硬性场景。

| # | As a… | I want… | So that… |
|---|---|---|---|
| US1 设备上线 | 用户 | 每台设备启动守护进程后**自动被发现并注册**到 AgentMesh，实时显示在线/离线 | 我能一眼看到当前可用的 agent 能力池 |
| US2 能力探测 | 用户 | 系统**自动探测**每台设备装了哪些 agent 平台及版本 | 我无需手动配置清单 |
| US3 任务下发 | 用户 | 从 Web 看板下达一个任务（如「修复这个 bug」） | 系统自动分派给最合适的设备上的 agent |
| US4 跨设备调度 | 用户 | 任务**自动路由**到具备对应 agent 平台且空闲的设备 | 主设备关机时，任务也能在别的设备完成 |
| US5 微信下发 | 用户 | 在个人微信 / 企业微信里直接发消息下任务 | 人不在电脑前也能远程指挥团队 |
| US6 实时监控 | 用户 | 在看板实时看到设备/agent/任务的调用关系与运行状态 | 快速定位问题、判断进度 |
| US7 断线降级 | 用户 | 设备离线时任务**不静默丢失**（重排/等待/告警） | 结果可靠，我能收到异常通知 |
| US8 结果回收 | 用户 | 任务结果**自动回传**到下发入口（看板/微信） | 无需主动轮询 |

## 5. 需求池

**优先级定义**：P0 = MVP 必须 · P1 = 首版后快速迭代 · P2 = 长期演进

### P0（MVP 必须项）

| ID | 需求 | 说明 / 验收标准 |
|---|---|---|
| P0-1 | 设备注册与局域网发现 | 守护进程启动即注册；mDNS/Bonjour 发现同网段设备；设备有唯一 ID；心跳保活 |
| P0-2 | Agent 平台探测 | 运行时自动探测设备已装 agent（Codex CLI / Claude Code / DSH / Grok 等）及版本、可用性 |
| P0-3 | 统一 Adapter 层 | 定义统一任务协议（下发/流式返回/取消）；≥4 种平台各一个 Adapter；新增平台不改调度核心 |
| P0-4 | 基础任务调度 | 单任务→单 agent；支持指定设备/agent 类型或自动选择；任务入队、执行、完成、失败、取消状态机 |
| P0-5 | 局域网直连通信 | 同网段设备间点对点任务下发与流式结果回传 |
| P0-6 | 任务结果回收 | 结果（文本 + 关键日志）回传到发起入口并持久化 |
| P0-7 | Web 看板（基础版） | 设备列表 + 任务列表 + 基础状态展示 + 手动下发任务 |
| P0-8 | 基础断线检测 | 心跳超时判离线；离线任务标记「中断」并告警，不静默丢失 |

### P1（应该）

| ID | 需求 | 说明 |
|---|---|---|
| P1-1 | 云端 WebSocket 中继兜底 | agent 出站连中继穿透 NAT/防火墙；局域网不可达时自动降级到中继 |
| P1-2 | 智能路由调度 | worker 注册/认领（claim）+ `max_agents` 并发限流；按 agent 类型/负载/空闲度路由 |
| P1-3 | 微信入口 | 个人微信 + 企业微信收发消息；消息→任务解析（LLM 语义或规则）；结果回推 |
| P1-4 | 动态神经图看板 | 力导向图实时呈现「设备→agent→任务→消息流」拓扑（详见 UI 文档） |
| P1-5 | 断线降级策略 | 任务重排到其他设备 / 等待队列 / 微信+看板告警 |
| P1-6 | 会话与任务历史 | 历史任务检索、执行日志回放 |

### P2（可以）

| ID | 需求 | 说明 |
|---|---|---|
| P2-1 | 子智能体并行 | 大任务拆解为并行子会话（借鉴 grok subagents），多 agent 协同 |
| P2-2 | 角色/模型路由 | 不同任务类型路由到不同 agent/模型/人格 |
| P2-3 | 分布式记忆 | 跨设备、跨会话记忆与上下文继承 |
| P2-4 | 多用户/团队 | 多人共享设备池、权限隔离、认领队列 |
| P2-5 | 权限规则 | allow/deny、工具过滤、危险操作前用户确认 |
| P2-6 | 技能/MCP 生态 | 技能市场、MCP server 注入 |

## 6. 核心功能模块清单

| 模块 | 职责 | 关键点 |
|---|---|---|
| M1 设备网格层 | 设备注册、发现、心跳、在线状态、能力上报 | mDNS 发现 + 唯一 ID + 心跳 |
| M2 Adapter 适配层 | 探测已装平台、统一任务协议、流式回传 | 每平台一个 Adapter；统一 stdin/流式事件模型 |
| M3 调度编排层 | 任务队列、路由、认领/限流、断线重排 | 借鉴 grok worker 注册/认领 + max_agents |
| M4 通信传输层 | 局域网直连 + 云端中继兜底、安全通道 | 局域网优先，中继 agent 出站连接 |
| M5 任务生命周期 | 创建/排队/执行/完成/失败/取消 + 状态机 | 状态机 + 事件流 |
| M6 可视化看板 | 神经图拓扑 + 列表 + 任务详情 | 实时、可交互 |
| M7 微信网关 | 个人微信 + 企业微信消息收发、任务解析 | 消息↔任务双向 |
| M8 会话与记忆 | 历史持久化、检索、跨会话上下文 | 借鉴 uuid 目录 + jsonl + sqlite |
| M9 权限与安全 | 设备认证、token、工具过滤 | 设备间信任模型 |

## 7. 界面文字版设计稿（Web 看板）

### A. 神经图主页（默认首页）
- **定位**：全局态势一屏看清，兼顾快捷下发。
- **布局**（三栏）：左侧导航栏 → 中央动态神经图（主区）→ 右侧可收起的信息抽屉。
- **顶部**：全局搜索 + 新建任务按钮 + 连接状态（局域网/中继）指示灯。
- **中央神经图**：力导向图，节点=设备/agent/任务/消息流，连线=调用/返回/流式（细节见 UI 文档 §4）。
- **右侧抽屉**（默认收起）：点击节点后展开，显示节点详情 + 快捷操作（下发任务/暂停/取消）。
- **底部状态条**：在线设备数 · 运行中任务数 · 告警数。

### B. 设备管理页
- **定位**：管理所有设备的注册、在线状态、agent 能力。
- **布局**：卡片网格（每设备一卡）。
- **卡片内容**：设备名 + 唯一 ID + 在线状态徽标（在线/忙碌/离线）+ 已装 agent 平台图标 + 负载/占用数。
- **交互**：点击卡片 → 进入设备详情页；右上「添加设备」→ 展示配对码 / 局域网发现结果。

### C. 任务中心页
- **定位**：任务列表 + 筛选 + 批量管理。
- **布局**：顶部筛选栏（状态/设备/agent 类型/时间）→ 任务表格/列表。
- **列表列**：任务名 · 状态徽标 · 目标设备/agent · 发起入口（Web/微信）· 开始/耗时 · 操作（详情/取消/重试）。
- **状态徽标**：排队/运行中/完成/失败/中断（颜色区分）。

### D. 任务详情页
- **定位**：单任务全生命周期视图。
- **布局**：顶部任务元信息（状态、耗时、目标设备/agent、发起入口）→ 中部消息流时间线（用户指令 → agent 思考/工具调用/输出，流式滚动）→ 底部操作（取消/重试/导出）。
- **消息流**：区分「用户输入 / agent 输出 / 工具调用 / 系统事件」四种气泡类型。

### E. 设备详情页
- **定位**：单设备健康与能力视图。
- **布局**：顶部设备元信息（名称/ID/在线状态/心跳时间）→ 已装 agent 平台清单（版本/状态/占用）→ 该设备任务历史 → 操作（下线/重启守护进程/移除）。

### F. 设置页
- **定位**：系统与账户配置。
- **分组**：① 通信（局域网开关/中继服务器地址）② 微信绑定（个人微信/企业微信扫码或配置）③ 权限（工具过滤、危险操作确认）④ 关于/版本。

### G. 微信入口（对话流）
- **定位**：任务下发的移动端入口（个人微信 + 企业微信聊天）。
- **交互范式**：聊天界面即下发入口——用户发一句话任务 → 系统回「已接收，任务 #ID，分配到 X 设备 Y agent」→ 执行中可推送关键节点 → 完成回传结果摘要（长结果附链接打开看板）。
- **命令约定**：支持自然语言 + 少量命令（如 `/status` 查队列、`/cancel #ID` 取消）。

## 8. 待确认问题清单

| # | 问题 | 影响 | 建议默认 |
|---|---|---|---|
| Q1 | 个人微信接入方式：非官方 API，采用 hook / 网页协议 / 第三方中转哪种？ | 稳定性、封号风险、合规 | 需康确认；企业微信优先（官方 API 稳），个人微信走受限通道 |
| Q2 | 云端中继自建还是用第三方服务？ | 成本、可控性、安全 | 默认自建轻量 WS 中继，仅做透传不存内容 |
| Q3 | 多设备装有同一 agent 平台时的调度优先级？ | 路由策略 | 默认「空闲优先 + 能力匹配优先」，可手动指定 |
| Q4 | 任务执行中设备关机/断网如何处理？ | 可靠性 | 默认中断标记 + 可重排到其他设备（P1） |
| Q5 | 设备间信任模型与认证方式？ | 安全 | 首次配对码 + 设备 token；中继仅透传加密载荷 |
| Q6 | agent 执行危险操作（删文件/联网）前是否需要用户确认？ | 安全 | 默认 P0 不拦截，P2 做工具过滤+确认 |
| Q7 | MVP 是否严格单用户？ | 数据模型复杂度 | 默认单用户，但设备/任务模型预留 owner 字段 |
| Q8 | 微信消息→任务的解析用 LLM 还是规则？ | 体验与成本 | 默认「规则优先 + LLM 兜底」 |
| Q9 | 数据存储位置（本地 vs 云端）？ | 架构 | 默认本地持久化，中继不存内容 |
| Q10 | 看板是否需移动端 H5 响应式（非仅微信）？ | UI 工作量 | 默认响应式但桌面优先（断点方案见 UI 文档 §5） |
